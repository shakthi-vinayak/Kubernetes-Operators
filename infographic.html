The Problem & The Solution

WITHOUT Operator

7+
  • Deployment YAML (50 lines)
  • Service YAML (20 lines)
  • HPA YAML (30 lines)
  • HTTPRoute YAML (40 lines)
  • NetworkPolicy YAML (25 lines)
  • PDB YAML (15 lines)
  • ServiceMonitor YAML (20 lines)
  • Total: 200+ lines per app

WITH Operator

1
  • Single PlatformApplication CR
  • ~40 lines of YAML
  • Auto-generates all 7 resources
  • Self-healing via drift correction
  • Production-hardened defaults
  • GitOps-ready
  • Multi-environment overlays
  • Total: 80% less YAML
How the Reconciliation Loop Works
1
FETCH — Get PlatformApplication from Kubernetes cache
|
2
COMPUTE — Each sub-reconciler builds desired child resources (pure functions)
|
3
APPLY — Server-Side Apply creates/updates resources idempotently
|
4
DETECT DRIFT — SSA compares desired vs actual; only writes on changes
|
5
UPDATE STATUS — Set Ready/Progressing/Degraded conditions + readyReplicas
|
6
REQUEUE — Retry on errors, re-check if replicas not ready
7 Resources Auto-Generated from 1 CR
D
Deployment
Always created. Container, replicas, probes, security
S
Service
Always created. Port mapping, selectors
H
HPA
When autoscaling enabled. CPU-based scaling
R
HTTPRoute
When gateway enabled. Gateway API routing
N
NetworkPolicy
When security enabled. Ingress/egress rules
P
PDB
When replicas > 1. HA during disruptions
M
ServiceMonitor
When metrics enabled. Prometheus scraping
